# 初步问题分析（讨论稿 v0.1）

> 针对 `00-原始商业规划.md` 的反向尽调。
> 目的不是否定方向，而是把"被乐观叙事掩盖的硬骨头"摆到桌面上，逐个回答后再动手。
>
> 整理日期：2026-04-27

## 一、战略层：文档自相矛盾的地方

### 1. "护城河浅" 与 "6 个月可卖 MVP" 互相矛盾
原文承认 "3D 转 BOM 护城河浅，6-12 个月会被开源 + 大厂 Copilot 抹平"，又把 "AI 主动 Agent" 列为代差壁垒。但**主动建议/预警/学习正是 SolidWorks 2026/2027、Autodesk、PTC 都在做的事**，他们有 CAD 内核、装机量、几十年零件库。一个 4 人团队凭什么先于他们做出代差？需要更诚实的回答。

### 2. "做工程师助手不做平台" —— 但路径仍是平台路径
原文说不做平台，但阶段二要 "延伸到项目管理 + 成本核算"，阶段三 "考虑生态"。本质仍是平台，只是换了名字。**真正的单点战略应该是 18 个月内只做一件事**（如：非标设备方案级 BOM 报价 30 分钟出结果）。原文没把"单点"切到足够小。

## 二、技术层：被刻意轻描淡写的硬骨头

### 1. "3D 转 BOM" 真正难的是"映射"，不是"转"
- 真正卡脖子的是：**CAD 内部命名 → 供应商 SKU 的精准映射**
- 同一个直线导轨，工程师可能写 `HG25_导轨_左`、`LM-Guide-25`、`HIWIN-HG25`
- 这是**长尾匹配 + 知识库 + 反馈闭环**，不是 LLM prompt 能解决
- 原文对这个核心瓶颈基本没提

### 2. "方案级 3D 图识别核心模组" 是研究级问题
- 阶段 0 的 "AI 识别伺服/导轨/夹具" 不是 6 个月能搞定的工程问题
- **建议从 MVP 砍掉**，或用 "模组模板库 + 工程师手动标注" 替代

### 3. 怡合达 API 拿不到，价值主张缺一条腿
- FA 标准件 80%+ 覆盖，是非标 BOM 主体
- 工程师在工具里看到 "米思米有价、怡合达没价"，体验直接崩
- 原文放在风险提示一笔带过，**这其实是产品能否成立的前提**
- **必须在动手前先去敲怡合达 BD 的门探底**

### 4. 米思米 / 京东工业 API 的"商用条款"风险
- 这些供应商开放平台**多数禁止把价格数据"二次包装后向第三方收费"**
- 在 SaaS 里展示给客户看可能违 ToS
- **先把每家 ToS 读一遍**

### 5. 工程量被低估
- SW 插件 + 后端 Agent + Web 控制台 + 4 家供应商集成 + 数字签名 + 私有部署
- 名义 24 人月（4×6），扣除调研/试用部署/招聘 onboarding，**实际有效开发只有 12-15 人月**
- 建议：原生 SW 插件推到第 9-12 个月，前 6 个月只做旁路助手 + 单一供应商深度集成

## 三、商业层：财务与销售路径站不住

### 1. 100 家付费 × ¥499 = ¥5 万/月，养不起 4 人团队
- 一线城市 4 人团队成本 ¥15-20 万/月
- 6 个月烧 ¥100-150 万换来 ¥5 万/月 ARR：典型 "PMF 验证成功但商业模型不通" 陷阱
- 要么定价上一个数量级（¥3-5k/月，对应阶段 2 老板买单），要么获客上一个数量级（500 家+）

### 2. 工程师付费 vs 老板付费是两个不同的产品
| 维度 | 工程师场景（阶段1） | 老板场景（阶段2） |
|---|---|---|
| 频次 | 高频 | 低频 |
| ARPU | 低 | 高 |
| 卖点 | 省时间 | 省采购成本 |
| 销售路径 | PLG | SLG |
- 6 个月只能选一条主线

### 3. 冷启动死锁
- "主动学习" 需要客户 3-5 个历史项目数据
- 新客户上线第一天没数据 → 价值体现不出来 → 激活率低 → 流失
- 原文没有冷启动方案
- 备选：预置 "行业通用知识库" 当垫片，或先服务 "愿意导入历史 BOM" 的种子客户

### 4. 6 个月 100 家付费在制造业 SaaS 极激进
- 中小制造企业决策周期典型 3-6 个月（工程师试 → 项目经理评估 → 老板审批）
- 意味着前 3 个月几乎没有付费转化
- 全部 100 家要在后 3 个月集中拿下，对销售团队要求远超 "4 人 + 1 业务"

## 四、原文档结构性缺失

| 缺什么 | 为什么重要 |

| "放弃指标" | 什么情况下应该认输停掉这个方向 |

## 五、动手前建议先做的三件事（每件 1-2 周）

1. **客户访谈**：5-10 家目标客户（非标自动化设备厂的工程总监 + 老板），把产品 mockup 描述给他们听，问：会不会用？愿意付多少钱？阻力在哪？
2. **API 探路**：探怡合达、米思米、京东工业的 BD，明确 API 商用条款和拿到时间表。怡合达若拒绝，需重新设计价值主张
3. **明确产品边界**：与现有 PEBS_lean_AI 的关系（虽然此项目独立，但客户群、品牌、销售可能有交集需要明确）

## 六、若直接动手，强烈建议的收窄 MVP

- 只做 **阶段 1（详细设计的 BOM 伴侣）** 一个场景
- 只接 **米思米 + 立创** 两家 API（绕开怡合达验证模式）
- 只做 **旁路桌面助手**（不做 SW 插件）
- 只服务 **3-5 家深度种子客户**（不追求 100 家）
- 6 个月目标改为：**3 家付费 + 验证 PMF 信号**（NPS / 留存 / 续约意愿）
