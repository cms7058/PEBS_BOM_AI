## 一、市场前景与竞争格局

### 1.1 市场顺风明显

**痛点真实存在：**
- BOM错误造成项目高达 23% 的成本超支
- CAD到ERP的BOM转移占工程师 20% 的工作时间
- 一台150万的非标设备，BOM出错可能导致5-15万的损失

**市场容量：**
- AI Agent市场预计2026年达 120.6亿美元，CAGR 45.5%
- 制造业 53% 的厂商倾向AI Copilot模式而非全自动化
- 中国非标自动化设备市场规模超3000亿，CAGR约15%

### 1.2 竞争格局：三层玩家

**第一层：CAD原生免费功能（不构成核心威胁但是基线）**

| 软件 | BOM能力 | 局限 |
|---|---|---|
| SolidWorks | 自带BOM表 | 不联通供应商，不做智能推荐 |
| Fusion 360 | 自带BOM | 同上 |
| Creo / Inventor | 自带BOM | 同上 |

结论：它们解决"有BOM"，不解决"BOM之后怎么办"。

**第二层：CAD插件型工具（最直接竞品）**

| 产品 | 核心功能 | 弱点 |
|---|---|---|
| Bommer | SW/Fusion插件，BOM元数据管理 | 老一代被动工具，无AI |
| OpenBOM | BOM+PDM+PLM平台 | 已是10年老平台，体系庞大但臃肿 |
| 3DViewStation | 浏览+BOM导出 | 偏可视化，弱业务集成 |
| Genius CAD2BOM | 简易转换工具 | 功能单薄 |

关键观察：OpenBOM已经在做"BOM AI Agent + Digital Thread Agent + Composable PLM"，他们看到了同样的方向。

**第三层：AI原生新玩家（潜在威胁）**

- Energent.ai — 自称BOM领域的AI Copilot
- Dirac BuildOS — 制造业AI操作系统理念
- GitHub上多个开源项目 — 学术圈和爱好者已在试

### 1.3 残酷的真相

> ⚠️ "3D转BOM"本身护城河浅，付费理由是BOM之后的事 —— 自动选型、对接供应商、ERP/PLM打通、成本预警、智能推荐。
>
> 如果你只做BOM转换，6-12个月就会被开源项目+大厂Copilot抹平。

## 二、关于"BOM入口→平台生态"战略的反思

### 2.1 这个想法不是不好，是已经被人走过

OpenBOM走这条路 **整整10年**，目前他们已经部署：
- BOM AI Agent
- Digital Thread Agent
- Composable PLM 架构

### 2.2 三个不能回避的事实

**❌ 事实1：BOM是节点，不是入口**

工程师每天的工作流：
```
打开SolidWorks → 设计 → (BOM在中间环节) → 出图 → 交付
```

老板/采购的工作流：
```
打开ERP → 看订单 → 看采购 → (BOM是参考数据)
```

没有人"打开BOM工具开始一天的工作"。把BOM当成入口，是把一个中间产物当成主角。

**❌ 事实2：平台生态是"结果"，不是"策略"**
- Salesforce 第8年才有AppExchange
- 钉钉/飞书做了5年才生态成型
- 平台是被生态选择的，不是规划出来的

先解决一个具体问题，做出一个让人离不开的产品 —— 生态自然来。

**❌ 事实3：每一个"扩展技能"都是红海**

| 你想做的事 | 已经在那里的玩家 |
|---|---|
| 项目管理 | 飞书、钉钉、Teambition、Worktile |
| MES / 制造执行 | 黑湖智造、新核云、SAP DMC |
| 成本核算 | 金蝶、用友、SAP |
| 供应链 | 震坤行、京东工业、米思米 |

每个领域都有几百亿市值的对手在等你。

### 2.3 推荐的替代战略：AI原生单点突破

**不要做"BOM平台"，做"非标设备工程师的AI助手"。**

差异：
- 平台思维：覆盖多个角色、多个场景，做大而全
- 单点思维：只服务一个角色（非标设备工程师），做深做透

## 三、供应链API接入分析

非标设备的BOM核心物料分布：

| 类别 | 占BOM比例 | 主要供应商 | API状况 |
|---|---|---|---|
| 电子元器件 | 10-15% | 立创商城 | ✅ 有开放平台 |
| MRO/工业品 | 20-30% | 震坤行、京东工业 | ✅ 有开放平台 |
| 自动化标准件 | 30-40% | 米思米、怡合达 | ⚠️ 米思米较开放，怡合达保守 |
| 机加工件 | 15-25% | 各地零散加工厂 | ❌ 无标准化API |

### 3.1 立创商城

- 机会：立创开放平台已上线，可获取价格、库存、参数。
- 威胁：立创自己已经做了免费的BOM配单工具（PCB场景）。
- 结论：在机械件、紧固件、气动液压件、传感器、电机这些立创搞不定的领域，机会大。

### 3.2 震坤行

| 项 | 内容 |
|---|---|
| 开放平台 | openapi.zkh360.com |
| 认证方式 | OAuth |
| QPS | 10 |
| Base URL | https://openapi.zkh360.com/api/v2 |

潜在威胁：震坤行2023年7月在太仓建了非标精密金属加工件智能制造工厂，他们也在往非标走。

### 3.3 京东工业

- 央国企渠道强势
- 开放平台成熟
- 必须接入

### 3.4 米思米（MISUMI）

- 非标设备工程师的"日常"
- 没接米思米，工程师不会用你的工具
- 必须重点接入

### 3.5 怡合达（关键变量）

- A股上市，市值约400亿
- FA标准件覆盖率 80%+
- API开放程度低、保守
- 是合作伙伴还是竞争对手？决定你能走多远

> 💡 **战略选择：**
> - 路线A（中立工具）：多供应商比价，工程师视角友好。**建议选这条。**
> - 路线B（渠道帮手）：深度绑定1-2家供应商，拿渠道返点。短期收入快，长期天花板低。
>
> 建议路线A，因为非标厂老板对供应商绑定高度警惕。

## 四、非标设备行业深度分析

### 4.1 五阶段典型工作流

**阶段0：方案报价（项目前1-2周）⭐⭐⭐⭐⭐ 最高价值**

现状：
- 销售带工程师勘察后，3-5天给报价
- 工程师Excel拉粗BOM，精度±20%
- 亏单的雷在此埋下

智能体价值："方案级BOM快速估算"
- 上传粗装配图
- AI识别核心模组（伺服系统、导轨、夹具）
- 给出带置信区间的成本预估："本方案预估85-95万，置信度75%"

技术难点：方案级3D图很粗，需要训练专用视觉模型识别"这是多大的伺服"。

**阶段1：详细设计（第1-3周）⭐⭐⭐⭐⭐ 核心战场**

现状：
- BOM展开到 2000-5000行
- 工程师在 SW、米思米、怡合达、立创、震坤行 之间反复切换
- 工程师每天8小时所在的环节

智能体价值："实时BOM伴侣"
- CAD插件实时显示价格、货期、可替代品
- 在工程师正在用的工具里出现，不打断流程
- 强粘性产品

**阶段2：BOM审核下单（第3-4周）⭐⭐⭐⭐ 高价值**

现状：
- 老板付费意愿最强的环节
- 一台150万设备的采购优化能省 5-10万

智能体价值："采购自动化与异常预警"
- 直接对接立创/震坤行/京东工业/米思米API实时拉取价格库存货期
- 老板审批界面提示："本BOM比公司过去类似项目平均贵12%，建议复核以下5项"
- 自动生成采购单，一键下单

**阶段3：制造装配（第4-7周）⭐⭐⭐ 中等价值**

现状：黑湖智造、新核云、SAP DMC的地盘。
策略：不要硬刚MES。

智能体价值：轻量级
- ECO（工程变更）影响分析："这个零件改了，影响下游哪些工序"
- BOM版本看板
- 与MES系统集成，而不是替代

**阶段4：售后（第7-8周后）⭐⭐⭐ 长尾收入**

智能体价值："售后备件智能助手"
- 扫码查询最终BOM
- 沉淀成"售后备件商城"
- 售后毛利常比设备本身高

### 4.2 聚焦优先级

```
阶段1 (核心战场)  ━━━━━━━━━━ 必须做
阶段2 (老板买单)  ━━━━━━━━━━ 必须做
阶段0 (方案报价)  ━━━━━━━━     重点做
阶段3 (制造装配)  ━━━━           等2000+客户后再做
阶段4 (售后)      ━━━━           等2000+客户后再做
```

### 4.3 三大行业挑战

1. 怡合达是绕不过的山 — 谈合作还是做竞品需要早决策
2. 3D文件解析"脏数据"难度高 — 工程师命名不规范、属性不全是常态
3. 客户决策链复杂 — 工程师要省事、项目经理要成本可控、老板要利润可见，三个角色三个诉求

## 五、产品形态与技术方案

### 5.1 推荐架构：三层

```
┌─────────────────────────────────────────────┐
│   第一层：SolidWorks 插件（瘦客户端）        │
│   C# + .NET + SwAddin                       │
│   职责：读取数据 / 渲染UI / 调API           │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│   第二层：AI Agent 后端（核心大脑）          │
│   Python + FastAPI + LLM + 向量库 + PG     │
│   职责：识别 / 推理 / 调供应商API / 学习   │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│   第三层：Web 控制台                         │
│   React/Vue                                 │
│   用户：项目经理 / 采购 / 老板              │
└─────────────────────────────────────────────┘
```

### 5.2 SolidWorks 插件可行性

- ✅ SW API（COM/.NET）成熟，OpenBOM/Bommer都用这条路
- ✅ 可嵌入侧边栏面板（Task Pane）
- ✅ 可监听用户操作事件
- ✅ 可调用外部API

### 5.3 五个工程坑（必须提前知道）

**坑1：插件分发与客户IT管控**
- 必须做msi企业级安装包
- 必须支持离线激活（很多工厂内网）
- 必须有数字签名（不然Windows报警告）
- 预算：3-5万 + 2-4周工作量

**坑2：SW版本兼容**
- 至少兼容5年内版本（2020-2025）
- 不能用太新的API特性
- 每年新版发布要做兼容测试
- 常态：1名专职.NET工程师维护

**坑3：性能问题**
- 装配图常2000+零件，不能让SW卡顿
- 异步分析、增量计算、缓存机制必须做好
- 卡顿一次，第二天就被卸载

**坑4：数据安全**
- 只传元数据（型号、属性），不传3D几何
- 大客户必须提供私有部署版本
- 准备清晰的数据隐私协议

**坑5：SOLIDWORKS Partner Program**
- 申请达索官方认证
- 出现在合作伙伴列表，获得早期API访问
- 企业客户的信任背书，值得拿

### 5.4 实施路径：B → A 两阶段

**阶段一：旁路助手（3-4个月）**

形态：独立桌面应用，监听SW打开的文件

优点：
- 一份代码搞定 SW + Inventor + Solid Edge
- 不依赖SW API升级节奏
- 迭代快

缺点：
- 体验不是嵌入式，是侧边窗口
- 实时性稍差

**阶段二：原生SW插件（第5-6个月起）**

形态：嵌入SolidWorks侧边栏的深度插件
触发条件：阶段一获得至少30家付费客户验证后再投入

### 5.5 AI Agent 的差异化设计

**❌ 不要做这种Agent**：对话框，用户问什么答什么。

**✅ 要做这种Agent**：主动型工程助手 —— 观察、建议、预警、学习。

三个核心场景：

- **场景1：主动建议** —— 工程师拖入25mm直线导轨 → Agent弹出："注意：贵司过去标准是HG系列，这个MGN系列负载只有原来的60%，确认要切换吗？"
- **场景2：主动预警** —— 选了一个伺服电机 → Agent提示："此型号货期15天，您项目总装定在第28天，会延迟3天。可替代型号货期7天，差价280元。"
- **场景3：主动学习** —— 项目结束 → Agent总结："本项目实际比预估高8.3%，主要超支在伺服系统(+12%)，建议下次伺服预算系数从1.0调整为1.1。"

这是与OpenBOM/Bommer老一代CAD插件的真正代差。

### 6.4 三阶段商业目标

**第一阶段（0-6个月）：单点突破"工程师神器"**
- 定价模式：免费试用 + 按BOM条数(0.5元/条) 或 包月(¥299/¥499/¥999)
- 目标：6个月签约 100家 付费小厂
- 月收入目标：5-10万

**第二阶段（6-18个月）：从工具向项目协作延伸**
- 项目管理、成本核算自然生长
- 单客户ARPU提升3-5倍
- 月收入目标：50-100万

**第三阶段（18个月后）：考虑生态**
- 客户数2000-5000家
- 月收入百万级
- 此时再考虑平台/生态

## 七、核心结论与最终建议

### 7.1 五个核心判断

1. ✅ 市场真实存在 — BOM痛点是普遍刚需，不是创造需求
2. ⚠️ 3D转BOM本身护城河浅 — 必须延伸到BOM之后的价值
3. ❌ 不要做平台 — OpenBOM走了10年，你6个月做不出来
4. ✅ AI Agent是真正代差 — 主动型工程助手是新一代产品形态
5. ✅ 非标设备行业是最佳切入点 — 痛点深、付费意愿强、决策链短

### 7.2 三个不要做的事

1. ❌ 不要从一开始就做完美SW插件 → 先做旁路助手验证市场
2. ❌ 不要做"BOM平台" → 做"非标工程师助手"
3. ❌ 不要做被动对话框 → 做主动型Agent

### 7.3 三个必须做的事

1. ✅ 聚焦阶段1（详细设计）和阶段2（采购下单） — 工程师粘性 + 老板付费意愿
2. ✅ 接入米思米 + 震坤行 + 立创 + 京东工业 — 不接，工程师不会用
3. ✅ AI Agent差异化设计：主动建议 / 主动预警 / 主动学习 — 这是你与老玩家的代差

### 7.4 一句话战略

> "做非标设备工程师每天打开SolidWorks时身边的AI助手 —— 主动思考、主动建议、会学习。先在3个月内用旁路助手验证需求，再投资做深度SW插件集成。先把100家小厂服务好，平台和生态自然会来。"
