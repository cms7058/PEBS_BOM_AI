# 数据获取策略

> 日期：2026-04-28
> 状态：进行中（等立创审核）
> 起因：米思米、震坤行 API 申请被拒，对原始商业规划 [00-原始商业规划.md](00-原始商业规划.md) 的"实时比价"价值主张构成根本挑战

## 一、问题定性

原始规划中，BOM 伴侣的核心价值主张依赖供应商 API：实时价格、货期、可替代品、自动下单。米思米和震坤行明确拒绝 API 接入后，需要重新评估数据通路。

## 二、备选路径评估（按推荐度）

### 路径 1：客户授权抓取（最务实）
浏览器扩展，工程师在自己的米思米/怡合达账号里浏览时，扩展实时读取页面数据。

- 法律定性：客户管理"自己看到的数据"，不是分发供应商数据
- 技术：SPA 页面解析有成本，但成熟方案
- 缺点：实时性受工程师主动浏览的限制；怡合达反爬可能严

### 路径 2：客户私有数据沉淀（核心方向）
价值主张从"实时价格"换成"**你公司过去的成交价 / BOM 知识库**"。

- 客户上传历史报价单、Excel BOM、采购订单 PDF
- OCR + LLM 抽成结构化数据
- 沉淀 6 个月后，每次新报价能对比"我们去年这个件买多少钱、谁家最便宜"
- **关键**：这是真正属于客户的数据壁垒，米思米/怡合达永远拿不走

### 路径 3：先打有 API 的供应商
- **立创商城**：开放平台 [open.jlc.com](https://open.jlc.com/) ——已注册，等审核（2026-04-27 提交）
- **京东工业**：[jos.jd.com](https://jos.jd.com/) ——主要是商家 ISV 路径，纯做工具的初创公司申请门槛高；建议同时走 [industrial.jd.com](https://industrial.jd.com) 商务 BD 路径
- 这两家加起来覆盖典型非标 BOM 的 30-40%（电子 + MRO 大类）

### 路径 4：邮件 / PDF 报价单解析
工程师/采购日常会收到供应商发来的报价邮件、Excel、PDF。

- 接入客户邮箱（OAuth）或文件上传
- LLM 把非结构化报价 → 结构化数据
- 完全不依赖任何供应商 API
- 反而能覆盖到米思米/怡合达 + **机加工厂报价**（这部分本来就没有 API，是非标 BOM 里 15-25% 的盲区）

### 路径 5：跟代理 / 经销商合作（不推荐先做）
覆盖窄、报价不一致，容易把产品做歪。

## 三、需排除的伪选项

**警告：CSDN、阿里云开发者社区上推的 `vipmro.item_get` 这类"京东工业 API" 99% 是第三方代理 API**：

- 京东宙斯 JOS 官方接口命名规范是 `jingdong.xxx.xxx`
- `vipmro.item_get` / `taobao.item_get` / `jd.item_get` 这种命名是 onebound、taobaoapi2014 等爬虫 API 中介公司的统一风格
- 违反京东 ToS，随时被封，且把法律风险绑在产品上
- **不要使用、不要付费购买他们的 SDK**

## 四、战略转向

如果四家关键供应商里有两家都拒绝给 API，市场已投了反对票。考虑把核心价值主张从"**帮你比价省钱**"换成"**帮你管 BOM 少出错 + 加快设计 + 沉淀公司知识**"：

| 旧定位 | 新定位 |
|---|---|
| 实时价格 / 货期 / 替代品 | BOM 结构化 + 版本管理 + ECO 影响 |
| 依赖供应商 API | 依赖客户自己的数据 |
| 价值靠外部数据壁垒 | 价值靠客户私有知识沉淀 |
| 米思米一家不给 API 就崩 | 任何一家不给都不影响核心 |
| 老板买单（采购降本，万元/年）| 工程师 + 老板共同买单（千元-万元/年）|
