# PEBS BOM 数据库生产部署与迁移方案

更新日期：2026-05-04

## 1. 部署模式

PEBS BOM 保留同一套代码和同一套数据库模型，通过环境变量区分部署场景：

| 场景 | DEPLOYMENT_MODE | TENANT_MODE | 推荐数据库 | 说明 |
| --- | --- | --- | --- | --- |
| 本地开发 / 演示 | private | single | SQLite | 快速启动，允许 `DB_AUTO_CREATE=true` |
| 客户私有化生产 | private | single | PostgreSQL | 单客户、单租户，所有数据使用 `DEFAULT_TENANT_ID=default` |
| PEBS 云服务器版 | cloud | multi | PostgreSQL | 多租户生产，后续由登录认证解析 `tenant_id` |

结论：SQLite 只作为本地开发和轻量演示数据库；私有化部署和云服务器生产都建议使用 PostgreSQL。私有化部署不是多租户，但仍保留 `tenant_id` 字段，便于同一套代码、迁移脚本和导入导出机制稳定运行。

## 2. 环境变量

私有化生产：

```bash
DEPLOYMENT_MODE=private
TENANT_MODE=single
DEFAULT_TENANT_ID=default
DATABASE_URL=postgresql+asyncpg://pebs:你的密码@postgres:5432/pebs_bom
DB_AUTO_CREATE=false
```

云服务器生产：

```bash
DEPLOYMENT_MODE=cloud
TENANT_MODE=multi
DATABASE_URL=postgresql+asyncpg://pebs:你的密码@postgres:5432/pebs_bom
DB_AUTO_CREATE=false
```

## 3. 迁移策略

生产环境不再依赖应用启动时自动 `create_all`。数据库结构升级统一使用 Alembic：

```bash
cd /Users/mingyue/PEBS_BOM/apps/api
.venv/bin/pip install -r requirements.txt
.venv/bin/alembic -c alembic.ini upgrade head
```

本地 SQLite 开发可以继续使用：

```bash
cd /Users/mingyue/PEBS_BOM/apps/api
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

## 4. SQLite 到 PostgreSQL 数据搬迁

先导出 SQLite：

```bash
cd /Users/mingyue/PEBS_BOM/apps/api
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/export_sqlite_json.py --sqlite data/app.db --out data/sqlite-export.json
```

再导入 PostgreSQL：

```bash
cd /Users/mingyue/PEBS_BOM/apps/api
DATABASE_URL=postgresql+asyncpg://pebs:你的密码@localhost:5432/pebs_bom \
.venv/bin/python scripts/import_json_postgres.py --in data/sqlite-export.json
```

导入前建议先完成一次数据库备份；正式迁移时应在停机窗口内执行，避免 SQLite 和 PostgreSQL 同时写入造成数据分叉。

## 5. 与现有系统对接

建议把 PEBS BOM 的数据层分为三类接口：

1. 主数据接口：公司标准物料、品牌、类目、供应商、别名映射。
2. BOM 业务接口：BOM、节点、层级、映射状态、编辑记录。
3. 智能体事件接口：对话触发的查询、导入草稿、确认写入、页面跳转事件。

对接 ERP / PLM / MES 时，优先通过 API 或定时同步任务对接主数据，不建议直接让外部系统写 PEBS 数据库。这样智能体可以继续保留确认、审计、候选映射等业务规则。

## 6. 后续开发顺序

1. 将云版认证接入后，把 `TENANT_MODE=multi` 的租户解析从固定值改为请求上下文。
2. 为物料、品牌、类目、BOM 节点补齐 tenant 级唯一约束和软删除策略。
3. 建立标准物料导入任务表，支持大文件异步解析、进度展示、失败行回放。
4. 增加数据库备份、恢复、迁移演练脚本，作为私有化交付包的一部分。
