# 智能体开发进展

> 日期：2026-05-01
> 依据：`docs/conversations/` 对话记录、`README.md` 路线图、当前代码实现
> 结论：PEBS_BOM 已经从概念验证进入可用产品早期阶段；BOM 对话编辑助手 1.0 已成型，正在补 Layer 1 的工程知识能力。

## 一句话判断

当前智能体不是还在"想法阶段"，而是已经有一个能跑、能演示、能继续迭代的产品底座。

它已经完成了 3D / Excel 到 BOM、图谱和表格联动、对话式编辑、审计历史、导出等基础能力；近期又开始补非标件分类、品牌知识库、品牌推荐和模型接入。下一阶段的真正关键，是把它从"能编辑 BOM 的助手"推进成"能沉淀客户工程知识的助手"。

## 当前位置

按 `03-产品架构与下一步.md` 的四层架构看：

| 层级 | 定义 | 当前状态 |
|---|---|---|
| Layer 0 | 3D / Excel → BOM 引擎 | 基本完成 |
| Layer 1 | 核心钩子，比 Excel 好 10 倍 | 已做 65-75%，正在补工程知识能力和交互闭环 |
| Layer 2 | 自有 skill，如比价、报价单解析、采购单 | 设计完成，尚未系统化落地 |
| Layer 3 | 开放第三方 skill | 暂不考虑 |

更具体一点，当前处在：

> P0 / P1 基础产品完成，Layer 1 智能能力已开工但未补齐，skill 架构仍处于设计阶段。

## 当前最合理的开发路线

### 第一优先级：SKU 智能映射 MVP

目标：让 BOM 里的原始零件名能沉淀成公司内部标准物料。

建议做法：

1. 新增 `Part` / `PartAlias` 数据模型
2. 在 BOM 节点上增加 `part_id` 或 `canonical_*` 字段
3. 做一个"待确认映射"接口
4. 前端加一个轻量确认弹窗或侧栏
5. 先支持人工确认 + 简单模糊匹配，再引入 LLM 建议

这是从"编辑器"走向"知识库"的第一步。

### 第二优先级：历史数据沉淀

目标：让客户第二次、第三次导入 BOM 时能感受到系统变聪明。

建议做法：

1. 每次 BOM 确认后，将节点映射结果写入公司知识库
2. 新 BOM 上传时自动查历史相似件
3. 前端展示"历史用过 / 可能重复 / 建议复用"
4. Agent 可以回答"这个件以前用过吗"

### 第三优先级：风险预警

目标：给工程师一个每天打开 PEBS_BOM 的理由。

建议做法：

1. 先做规则引擎，不急着 LLM
2. 在 BOM 表格和图谱上展示风险标记
3. Agent 能解释风险原因
4. 风险结果写入审计或结构化字段，便于后续报告导出

## 暂时不建议做

| 暂不做 | 原因 |
|---|---|
| 完整 SolidWorks 插件 | 成本高，当前 Layer 1 还没扎实 |
| 完整第三方 skill 平台 | 现在还不到开放生态阶段 |
| 多租户 / 订阅系统 | 种子客户验证前投入产出不高 |
| 全量比价系统 | 外部数据通路未稳定 |
| 大而全的项目管理功能 | 会稀释 BOM 核心价值 |

## 阶段结论

PEBS_BOM 当前已经完成了"能生成、能看、能改、能对话操控"的第一阶段。

下一阶段的核心不是再堆更多工具，而是把每一次 BOM 编辑、分类、品牌选择都沉淀成客户自己的工程知识。只要 SKU 映射和历史沉淀跑通，这个产品就会从"方便的 BOM 工具"变成"越用越有价值的工程智能体"。
