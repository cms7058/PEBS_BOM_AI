# PEBS BOM — 产品介绍

> 写作日期：2026-05-07
> 用途：客户首次接触材料、销售一页纸、产品图文介绍的源稿
> 维护：每加一个新模块就在「核心能力」追加一段，不要另写新文档

---

## 一句话定位

**PEBS BOM 是为长三角中小型设备制造商打造的 AI BOM 助手：把工程师乱写的零件名沉淀成公司自己的标准物料库，让每张 BOM 都比上一张聪明。**

不是 PLM、不是 ERP、不是另一个 Excel 插件。它解决一个具体的痛——

> 「这个件去年用过哪家供应商？为什么我又得问一遍？」

---

## 它解决谁的什么问题

### 客户画像

| 你是 | 你大概率有这些痛 |
|---|---|
| 50-500 人的精密自动化、锂电、机器人、医疗器械装配厂 | 每张 BOM 都是 Excel 手工拼，工程师写法不统一 |
| 用 SolidWorks + Excel 拼凑 BOM，没上 PLM | 「这个件谁选的、上次哪家、单价多少」靠口口相传 |
| 每年新项目 ≥ 5 个，重复使用大量同类标准件/外购件 | 同一颗螺丝在 10 个项目里写成 10 种叫法，采购难合单 |
| 想沉淀公司知识但买 PLM 太重 | Excel 散落、Teamcenter 太贵且实施周期半年起 |

### 不适合谁

- 单 PCBA 电子厂（立创/Altium 体系完整，BOM 已自动）
- 简单加工件代工（BOM 太简单不需要工具）
- 大型主机厂（已有 Teamcenter / 3DEXPERIENCE）

## 核心能力

### 1. 智能解析 — 5 秒生成结构化 BOM

| 输入 | 输出 |
|---|---|
| `.xlsx` / `.xls` / `.csv` | 自动识别字段、推断层级、生成可编辑 BOM |
| `.step` / `.stp` / `.iges` / `.igs` 装配文件 | 解析装配树（不渲染几何，避免大零件卡顿） |

- 字段映射靠规则 + LLM 兜底，常见格式开箱可用
- 层级识别支持零件号前缀（`A.01.02`）、缩进格式、显式 parent 列三种主流写法
- 解析失败的字段会让用户在表格里直接补，不卡流程

### 2. 对话式编辑 + 多视图联动

界面分三块：**结构图（G6 流程图）/ 表格（AG Grid） / 智能体侧栏**。三处任意修改，另外两处实时同步。

智能体能做的事（部分）：

- 节点增删改查：「在电机组件下加一个编码器，数量 1」
- 批量样式：「把所有外购件高亮，加 OEM 标签」
- 单个 slot 精修：「把这张卡片的标题字号调大」
- 类目分类：「这个是什么类目？」「给所有非标件分类」
- 操作可审计、可撤销：每次编辑写一条 audit log

### 3. 公司标准物料库 — 越用越聪明

这是 PEBS BOM 真正的护城河，不是 BOM 工具，是 BOM **沉淀器**。

#### 3.1 主数据沉淀

每次客户在节点上确认「这就是我们公司的标准 X」，系统自动：

- 创建（或复用）`Part` 主记录：标准名、SKU、品牌、类目、规格
- 把当前节点的"原始写法"作为 `PartAlias` 沉淀（下次再写错也认得）
- 累计 `usage_count` + 更新 `last_used_at`

#### 3.2 智能映射 — 4 层兜底

新 BOM 上传时，每个未映射节点会被打分，给出候选清单。打分逻辑分四层，**逐层兜底**：

| 层级 | 触发条件 | 典型场景 |
|---|---|---|
| 精确匹配 | 零件号 / 标准名完全相同 | `N-M5` 直接命中 `Nut M5` |
| 历史别名 | 节点写法在过往 alias 里出现过 | `子装配件`→ 命中曾被映射过的别名 |
| Fuzzy 词元 | 词元 Jaccard ≥ 阈值 + 节点全词被覆盖 | `ROOT` → `Root Assembly` |
| 跨 BOM 节点 | 同类目 + 共有词 + 历史已 confirm 节点 | 上次 BOM-A 的「电池包 36V」→ 推荐到这次的「锂电池组 36V」 |

每条候选展示：标准物料名、品牌、相似原因、历史使用次数、上次使用时间，以及**可点击跳转**的「曾在 BOM「X」节点「Y」」深链。

#### 3.3 一键操作

- **`✓ 选这个`**：单节点确认映射
- **`+ 新建标准物料`**：候选都不对时直接新建
- **`⚡ 一键确认高分候选`**：BOM 内所有 score ≥ 0.85 的强匹配批量映射，一键完成
- **`📋 打开物料库`**：跳转公司标准物料列表

### 4. 风险预警

7 条规则，毫秒级返回，不调外部数据：

| 风险 | 触发条件 | 等级 |
|---|---|---|
| 🚨 停用物料 | 映射到 status ≠ active 的 Part | critical |
| ⚠️ 未映射 | 节点没绑定标准物料 | warn |
| ⚠️ 未指定供应商 | node.supplier + Part.brand 都为空 | warn |
| ⚠️ 长货期件 | Part.typical_lead_time ≥ 30 天 | warn |
| ⚠️ 高价值件 | 数量 × 单价 ≥ ¥1000 | warn |
| ℹ️ 未分类 | 节点和 Part 都无类目 | info |
| ℹ️ 孤儿物料 | 映射到的 Part 全公司只用过 ≤ 1 次 | info |

风险标签三处可见：

- **节点卡片**：选中节点时顶部显示 chip
- **BOM 表格**：风险列展示最高严重度 + tooltip 列全部
- **BOM 图谱**：节点描边颜色（红/黄/蓝）

可对话查询：「检查一下这个 BOM 有什么风险」「哪些件需要关注」。

## 典型场景

### 场景 A：第一次上传

工程师把 SolidWorks 导出的 `xlsx` 拖进 PEBS BOM。

1. 5 秒后看到结构图 + 表格
2. 智能体侧栏提示：「这个 BOM 11 个节点都还没映射到公司标准物料」
3. 工程师点选其中 3 个关键件 → `+ 新建标准物料`
4. 公司物料库从 0 增长到 3 条；下次再传同类 BOM 这 3 件就会被自动识别

### 场景 B：第二次上传（同类机型）

同一工程师 / 不同工程师上传新机型的 BOM。

1. 上传完成后顶部 panel 显示「7/30 节点已有候选」
2. 点 `⚡ 一键确认高分候选`，5 个强匹配秒级完成映射
3. 剩余 2 个 fuzzy 候选在节点卡片里逐个 `✓ 选这个`
4. 工程师感觉「系统知道我们公司用什么件」——这是付费的转折点

### 场景 C：交付前风险审

技术总监打开下周要交付客户的 BOM。

1. 智能体侧栏顶部 risk panel 显示「⚠️ 11 · ℹ️ 5」
2. 在对话中问「列一下所有警告级以上的风险」，Agent 给清单
3. 总监看到「电机组件未指定供应商」「主板长货期 35 天」，分发给采购确认
4. 5 分钟前还可能漏的事，被规则兜住

## 数据安全 / 部署模式

| 模式 | 适用 |
|---|---|
| SaaS 公网（默认） | 试用、小客户、对数据敏感度低的场景 |
| 私有云 / 本地部署 | 客户工程数据不出厂；提供 Docker Compose 一键拉起，依赖 PostgreSQL + 对象存储 |

- 多租户：每个客户的 Part / Brand / BOM 数据物理隔离
- 审计：所有 BOM 编辑、映射确认、品牌录入都有 audit log
- 模型：默认走 DeepSeek，支持切换；模型调用日志不出客户租户

## 5 步上手

1. **注册账号** → 进入工作台
2. **上传第一张 BOM**（你手头任意一个 Excel 或 STEP 都行）
3. **跟智能体聊一会儿**：让它分类、调整样式、补字段
4. **沉淀第一批标准物料**：选 3-5 个最常见的件 → 新建标准物料
5. **再传一张同类 BOM**：体验自动候选 + 一键确认

5 步走完平均 30 分钟，能形成对产品的真实判断。

## 与替代方案的对比

| 你现在用 | PEBS BOM 比它强在 | PEBS BOM 不如它的地方 |
|---|---|---|
| Excel | 自动识别层级、对话式编辑、知识沉淀、风险预警 | 没有公式自定义灵活度 |
| SolidWorks PDM / Workgroup PDM | 不绑定 SolidWorks 文件、无需安装、按 BOM 而非按文件管 | 不管 CAD 文件版本控制 |
| 国产 PLM（华天 / 思普 / 开目） | 实施周期 30 天 vs 6 个月、年费 1/10、不需要 IT 配合 | 没有 ERP / MES 双向同步（路线图） |
| 自研脚本 | 不是一次性产物，越用越聪明 | 灵活度不如自己写 |
