## 轮次 4 — 助手：四维度反向尽调

完整内容已保存为 `docs/01-初步问题分析.md`。核心结论：

**战略层**
1. "护城河浅" 与 "6 个月可卖 MVP" 互相矛盾
2. "做工程师助手不做平台" —— 但路径仍是平台路径
3. 与现有 LeanAI 项目的关系完全没说

**技术层**
1. "3D 转 BOM" 真正难的是 CAD 命名 → 供应商 SKU 的映射，原文没提
2. "方案级 3D 图识别核心模组" 是研究级问题，6 个月做不出
3. 怡合达 API 拿不到，价值主张缺一条腿
4. 米思米 / 京东工业 API 的商用条款风险
5. 工程量被低估（实际有效开发只有 12-15 人月）

**商业层**
1. 100 家付费 × ¥499 = ¥5 万/月，养不起 4 人团队
2. 工程师付费 vs 老板付费是两个产品（PLG vs SLG）
3. 冷启动死锁（"主动学习" 需要历史数据）
4. 6 个月 100 家付费在制造业 SaaS 极激进

**结构性缺失**
- 数据冷启动方案 / GTM 路径 / 关键人员计划 / 怡合达应对 / 数据合规 / 放弃指标

**建议动手前先做三件事**
1. 5-10 家客户访谈
2. 怡合达 / 米思米 / 京东 BD 探路
3. 明确产品边界

**收窄 MVP 提案**
- 只做阶段 1（详细设计的 BOM 伴侣）
- 只接米思米 + 立创
- 只做旁路桌面助手
- 只服务 3-5 家深度种子客户
- 6 个月目标改为 3 家付费 + 验证 PMF
